# v0.6.0

**Released:** 2026-10-24 · **Branch:** `main` · **Previous:** [v0.5.2](v0.5.2.md) (2026-10-24).

The hosted service becomes **prepaid**: each account has a balance, tops it up through Stripe, is warned and
emailed as it runs low, and cannot start paid work once it is $50 below zero
(#1114). Also: people
whose Clerk profile has no name can sign in, and the sign-in page no longer loops on an error.

> **Read [Before it rolls](#before-it-rolls).** Migration `0099` and new Stripe events need an
> operator release first.

## Features

| PR | Change |
|---|---|
| #1118 | **Prepaid account balance** (billing on only). Balance = top-ups − charges, in Postgres with billing. Top-ups through Stripe Checkout: the first exactly $20, later ones $20 or more; each payment credited once from the webhook and audited. Charges refreshed every 5 minutes from each workspace's usage at the price list; a failed usage read holds the balance. **51 capabilities that start paid work answer `402 payment_required`** (balance, limit, Add funds link) when the balance is more than $50 below zero, or before an account's first top-up; reads, sign-in, stops and deletes stay open (`PaidWorkContract` fails on an unmarked one). A banner on every page, a `warnings` entry on REST and MCP answers, and emails (near the limit, below $0, blocked) sent once per crossing, all linking to `/billing/add-funds`. **Auto top-up, off by default**: a card saved through Stripe, charged off-session once per crossing, at most 5 a day; a decline turns it off and emails the owner. An issued invoice for a topped-up account is paid from the balance. Migration `0099_account_balances`. Settings: `LAKE_BALANCE_FIRST_TOP_UP_USD` (20), `LAKE_BALANCE_MINIMUM_TOP_UP_USD` (20), `LAKE_BALANCE_OVERDRAFT_USD` (50), `LAKE_BALANCE_WARNING_USD` (10), `LAKE_BALANCE_REFRESH_SECONDS` (300), `LAKE_AUTO_TOP_UPS_PER_DAY` (5) ([`../api/billing.md`](../api/billing.md)) |

## Fixes

| PR | Change |
|---|---|
| #1117 | **Sign-in with no name in Clerk** (#1115): the `lake` template's `name` is `null` for a Clerk user with no first or last name, and lake refused the token. A `null` name or email now counts as missing. A refused token logs `clerk_sign_in_refused` with the reason (never the token). After an error the sign-in page stops retrying and offers *Try again*. The invitation wording appears only where the Clerk instance's sign-up is restricted (#1116) |
| #1107 | Who owns the Microsoft sign-in app and what blocks its publisher verification (docs, #756) |

## Before it rolls

- **An operator release that vendors `db/schema.sql` through `0099_account_balances`** (guard
  `account_balances_guard`) and adds the Stripe events the balance needs to `lakeStripeWebhookEvents`:
  `setup_intent.succeeded`, `payment_intent.succeeded`, `payment_intent.payment_failed`, with
  `checkout.session.completed` and `checkout.session.async_payment_succeeded` on every billing Lake.
- **The Lake's restricted Stripe key (`appKey`) must be allowed to write PaymentIntents** (auto top-up).
- **Existing accounts start at $0**: on a billing Lake they must top up before starting paid work.
- Each Lake restarts once.
