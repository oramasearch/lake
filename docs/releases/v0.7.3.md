# v0.7.3

2026-10-26. A hotfix on top of [v0.7.2](v0.7.2.md), for a production outage. Image `oramasearch/lake:v0.7.3` (private).

## What it changes

- **Agents default to gpt-5.5 again** (#1248, issue
  #1245).
  - v0.7.2 made `gpt-6.1-sol` the default agent model.
  - OpenAI refuses a `/v1/chat/completions` request to the gpt-6.x models that carries function tools with
    `reasoning_effort`, and the library agents send exactly that. So every agent turn with tools failed on every
    environment: Ask Orama, the Project, Application and Experiments agents, and Quickstart's Ask Orama step.
  - `default_agent_model` is `gpt-5.5`. The console labels it as the default.
  - The gpt-6.x models stay choosable per workspace, and the docs say why they are not the default.

## Not included

- The gateway sending a gpt-6.x Chat Completions call that carries tools to `/v1/responses`. That comes in v0.8.0
  (lake#1244), and makes `gpt-6.1-sol` the default again.

## Known issues

- **Release defect, fixed on `dev` after the tag:** the tagged tree left `current_version()` in
  `include/lake/version.hpp` at 0.7.2 and this page's heading did not match its test, so two `ReleaseVersion` tests fail at
  the tag. `version_string()` (what `server_info` reports) is 0.7.3. Nothing a running Lake does depends on it.

- A workspace that chooses a gpt-6.x model gets the same refusal on its agents' tool calls until v0.8.0.
- As in [v0.7.2](v0.7.2.md#known-issues).
