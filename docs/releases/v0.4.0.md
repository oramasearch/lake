# v0.4.0

**Released:** 2026-10-21 · **Branch:** `main` · **Previous:** [v0.3.1](v0.3.1.md) (2026-10-20).

v0.4.0 is **the security release from the multi-tenant security audit** (epic
[#873](https://github.com/oramasearch/lake/issues/873)) **and the pre-launch security review**
(epic [orama-bridge#223](https://github.com/oramasearch/orama-bridge/issues/223), tracker
[#911](https://github.com/oramasearch/lake/issues/911)). It closes every Critical the review found in
Lake: no credential acts as the operator, `sign_in_sso` is operator-only, TAAP sign-in needs the key
bound to the identity, policy objects count only inside their own account, an application pool's
session carries no Lake grants, and the replication credential reaches only configured peers. It
adds **SAML sign-in** with Lake's own XML signature verification, **OpenID Connect discovery** for
Entra, Okta and Google Workspace, and **`delete_account`**. Everything in [v0.3.1](v0.3.1.md) is still
here.

## 5. Behaviour that changes

- **Sign-in.** A person's or organization's identity must be a TAAP id; any row that is not cannot
  sign in. TAAP sign-in after a rotation needs `identity_chain`. Password sign-up and a first OAuth
  sign-in with an identity document need `identity_proof`. An application pool's session reaches only
  its own sign-in capabilities.
- **OAuth MCP connections** signed in before this release sign in again; a bearer connection moved to
  another URL must name its secret again.
- **Replication** is refused until the operator sets `LAKE_REPLICATION_PEERS` and
  `LAKE_REPLICATION_TOKEN` (no deployment replicates today).
- **Webhooks** reach only HTTPS on public addresses. **Image apps** must be pinned by digest; stdio MCP
  connections answer `not_supported` until the operator's runner image is pinned
  (orama-operator#752).
- **Required reviews** count only a second person's approval with `review` rights; earlier approvals
  no longer count. **Root recovery** takes named participants; ceremonies begun before `0093` cannot
  be completed.
- **Exports** made by a non-administrator carry no grants, and no archive carries a webhook secret.
- **Model usage** of a dropped or usage-less answer is counted (estimated when the provider reports
  none).

## What `v0.4.0` does **not** include

Everything under v0.3.1's [*does not include*](v0.3.1.md) is still not included. Also not:
- **The proxy service** for Python agents' launches, which would stop a launch holding Lake's shared
  agent service token ([#1039](https://github.com/oramasearch/lake/issues/1039); #878 is on hold).
- **liquid#383's lake side** ([#1021](https://github.com/oramasearch/lake/pull/1021)), which waits for
  liquid#448 and liquid's pin.
- Encrypted SAML assertions, signed AuthnRequests, IdP-initiated sign-in and single logout.

## Known issues

Security-relevant first. All open at this tag. The pre-launch review's open findings in Lake are
tracked under [#911](https://github.com/oramasearch/lake/issues/911): 103 open issues carry the
`security` label.

- **Security: Python agent launches hold the shared agent service token**
  ([agent-runtime#14](https://github.com/oramasearch/agent-runtime/issues/14),
  [#1039](https://github.com/oramasearch/lake/issues/1039)). A user-created agent's code can call the
  library agents directly, outside Lake's dispatch and records.
- **Security, open p1 findings:** LSR-009 agent launch and schedule credentials escape their workspace
  ([#918](https://github.com/oramasearch/lake/issues/918)); LSR-010 anonymous ACME enrollment issues
  certificates under another customer's CA ([#919](https://github.com/oramasearch/lake/issues/919));
  LSR-011 Clerk email linking keeps an attacker's credentials
  ([#920](https://github.com/oramasearch/lake/issues/920)); LSR-012 Lake-template token exchange
  without origin binding ([#921](https://github.com/oramasearch/lake/issues/921)); LSR-013 a delegated
  agent turn is not attenuated ([#922](https://github.com/oramasearch/lake/issues/922)); LSR-014 Drive
  version operations read other node identities ([#923](https://github.com/oramasearch/lake/issues/923));
  LSR-015 Drive, methodology and model writes bypass protected branches
  ([#924](https://github.com/oramasearch/lake/issues/924)); LSR-016 GitHub import of a server-local
  directory ([#925](https://github.com/oramasearch/lake/issues/925)); LSR-017 the read-only SQL guard
  disagrees with Zetta's parser ([#926](https://github.com/oramasearch/lake/issues/926)); a folder
  administrator can create a sibling folder's path object
  ([#1030](https://github.com/oramasearch/lake/issues/1030)); a rotated-away first key still signs in
  ([#1024](https://github.com/oramasearch/lake/issues/1024)); user attestations are not yet verified
  against the issuer's chain ([#1020](https://github.com/oramasearch/lake/issues/1020)).
- **Security: login CSRF** for OIDC and SAML sign-in
  ([#1018](https://github.com/oramasearch/lake/issues/1018)). **Do not offer enterprise SSO to a
  customer until it is fixed.**
- **Sign-in:** enterprise OIDC cannot start on PostgreSQL
  ([#1022](https://github.com/oramasearch/lake/issues/1022)).
- **Accounts:** a deleted person's identity stays in audit events already written; whether GDPR needs
  them redacted is undecided ([#810](https://github.com/oramasearch/lake/issues/810)). The policy
  principal decisions in [#872](https://github.com/oramasearch/lake/issues/872) are open.
- **Archives exported before this release** may carry webhook secrets; owners who cannot rule out a
  reader's export should rotate theirs.
