# v0.7.1

**Released:** 2026-10-25 · **Branch:** `main` · **Previous:** [v0.7.0](v0.7.0.md) (2026-10-24) ·
**Tracking:** #1219, epic #1158.

A patch:
- **The Quickstart decides what to build with you.** Its model step is an Ask Orama conversation on the
  dataset you dropped. It trains on any column types, a clustering model trains, and every state after the
  conversation says what happens next. The website code comes as a copy-ready agent prompt.
- **A failed app tells you, and the Application Agent fixes it.** A failed rollout or build is a
  notification with *Fix with the Application Agent*; an app can be changed with instructions, and auto-fix
  is opt-in. The Apps page counts Degraded apps as needing attention.
- **Ask Orama's confirm card is readable**, and it never proposes a change that cannot work.
- **Auto-Suggest finds opportunities again**, and a scan survives leaving the page.

No migrations and no new environment variables since v0.7.0. Ships with agent-ask-orama v0.2.1 and
agent-application v0.2.1 ([Before it rolls](#before-it-rolls)).

## Features

| PR | Change |
|---|---|
| #1199 | **The Quickstart's model step is an Ask Orama conversation** (#1182). Once search works, *Decide What to Build* opens Ask Orama on the dataset: its name, row count, each column's kind and whether it can be predicted, and the index. It leads with ideas: a model, a target derived from a column (a threshold, bands or a set of values), M-3 clustering, Auto-Suggest opportunities, an analysis, or an app built by the Application Agent (such as a dashboard). Confirming a model trains it, and the steps continue. *Nothing to Predict Yet* is gone; *Choose the columns myself* stays as a fallback. New capability `start_quickstart_conversation`. `quickstart_status` names the conversation. `train_quickstart` gains `derived_target` and `methodology: "M-3"` (a clustering model is not published for the website: zetta serves predictions only for gradient-boosted models). The conversation lives in the workspace Zetta ([`../api/quickstart.md`](../api/quickstart.md)) |
| #1186 | **The Quickstart trains on any column types, detected automatically**, and never fails on `transform_required` (#1181). The training copy reads up to 1,000,000 rows and must fit `upload_dataset`'s 16 MiB (#1190) |
| #1187 | **Website code as a *Copy agent prompt* tab (the default)**, carrying the source and everything an agent needs to install it, beside a *Source code* tab (#1185) |
| #1218 | **A failed app is a notification, fixed or changed with the Application Agent, with opt-in auto-fix** (#1207). A background pass records a notification in the app's workspace Zetta when a rollout ends Degraded, Failed or crash-looping at the desired generation, or the newest build fails; Ready again resolves it. The Apps list shows a banner per failed app; the app page has *Fix or Change This App* (open notifications, *Fix with the Application Agent*, a *Change this app* box, and **Auto-fix**: off by default, 1 to 10 attempts, default 3). The agent proposes a diff; once confirmed it commits through `commit_repository_files` (liquid drips, attributed to the person) and redeploys. Auto-fix makes one attempt per failed generation as the person who turned it on, then stops and says so. *Account → Notifications* lists every notification of the workspace. New capabilities `list_notifications`, `dismiss_notification`, `get_auto_fix`, `set_auto_fix`, `repair_app`, `change_app`; `agent_turn` takes `kind: repair` or `change` for agent-application. Records: `lake_resource_notifications` and `lake_resource_repairs` in the workspace Zetta; nothing in Postgres ([`../api/notifications.md`](../api/notifications.md)) |

## Before it rolls

- **Schema:** unchanged since v0.7.0 (`git diff v0.7.0 v0.7.1 -- db/` is empty). The operator runs `lake migrate`
  from the image, which applies nothing new.
- **Settings:** nothing new is read from the environment (`git grep getenv` between v0.7.0 and v0.7.1 adds only
  the test variables `LAKE_TEST_ZETTA_URL` and `LAKE_TEST_ZETTA_TOKEN`); `environment_variables()` and
  `stripe_webhook_events` are unchanged. The new refusals are Lake's own (a repair turn naming another app, auto-fix
  past its attempts, a clustering of fewer than 2 rows) and need no setting.
- **Agents:** roll with **agent-ask-orama v0.2.1** (prompt v17: it follows the Quickstart's state after a confirm,
  agent-ask-orama#56) and **agent-application v0.2.1**
  (repair and change turns, agent-application#40; without
  it a repair turn gets the old new-app behaviour). The other agents stay at v0.2.0.
- **Apps with workspace data** start only once orama-operator#1001
  (the binding as JSON) is released and rolled (#1205).
