# v0.7.0

**Released:** 2026-10-24 · **Branch:** `main` · **Previous:** [v0.6.1](v0.6.1.md) (2026-10-24).

The first release after the hosted service's launch, gathered in #1158.
A new home page, **Quickstart**, takes a dropped dataset to search and model answers on your own
website. A **browser key** is the public credential that website holds. Orama can give **credits**
and run **coupon codes** for ads. **Signing out no longer revokes API keys.** A white-labelled Lake
gets its **customer's domain, sign-in and brand**. **`lake migrate`** and **`lake manifest`** let
the image apply its own schema. Plus security fixes and three memory bugs found by AddressSanitizer.

Four migrations (`0100` to `0103`), all additive. The schema reaches the control database before
the image rolls ([Before it rolls](#before-it-rolls)).

## Features

|---|---|
| #1157 | **Quickstart**, the new home page at `/` (Ask Orama moves to `/ask`; old links redirect). Drop a CSV or JSONL file: it becomes a dataset, a published search index, website code (plain page, React, curl) with a live search box, then **Train a Model** trains and publishes a model whose answers show beside each result. `start_quickstart`, `quickstart_status`, `train_quickstart` and `quickstart_snippets` on REST, MCP and the agent documents (*Start Here*). Each step calls the existing capabilities as the person, so permissions, the balance gate, audit and metering are theirs; progress is kept in the workspace Zetta ([`../api/quickstart.md`](../api/quickstart.md), #1128) |
| #1177 | **Browser keys** (`lbk.<id>.<secret>`): the credential a website's page holds. Bound to one workspace, one index and optionally one model; only `search_index` and `predict` on those; only from its listed origins (CORS answers those alone); a per-minute limit shared by every replica (600 by default). Not tied to any session: it lasts until revoked or its expiry. `create_browser_key`, `list_browser_keys`, `revoke_browser_key`; the Quickstart makes one in one click; Search Index gets *Website Keys*. Migration `0100_balance_grants` ([`../api/billing.md#credits-from-orama`](../api/billing.md#credits-from-orama), #1134) |

One redemption per account and per email (kept as a hash), new accounts only by default, failures rate-limited. Each region creates its own codes (#1159). Migration `0101_coupons` ([`../api/billing.md#coupon-codes`](../api/billing.md#coupon-codes), #1156) |
| #1147 | **`lake migrate`** applies the schema built into the image (one transaction, an advisory lock, JSON report, exit codes) and **`lake manifest`** prints what the image needs from the operator: the schema, its Stripe webhook events and products, and every environment variable it reads. `server_info` lists the Stripe events. ## Security and identity

| PR | Change |
|---|---|
| #1173 | **Signing out ends only that browser.** A Clerk sign-out used to revoke every session, API key and device of the account. Lake now binds each browser session to its Clerk session (the default session token's signed `sid`), and a session event ends only the browser it names. No sign-out ends a key, including keys made in that browser. A new **Sign out everywhere** (`sign_out_everywhere`, Sessions page) ends everything for your own account. Bans, locks, deletion and `revoke_user_sessions` still end everything. Migration `0103_clerk_session_binding` (#1163, #1172) |
| #1138 | Under Clerk, Lake's own password sign-up and sign-in in the `lake` pool are refused (`403`), by the same rule that makes `viewer` say `password_sign_up: false`; it was possible to skip Clerk's sign-up control (#1098, the provisioning step of the #920 fix) |
| #1133 | An unknown email takes as long to reject as a wrong password (a dummy Argon2id check), so response times no longer show which emails have accounts (#1101) |
| #1131 | Per-client limits believe `X-Real-IP` / `X-Forwarded-For` only from trusted proxies (`LAKE_TRUSTED_PROXY_CIDRS`; unset: loopback and the private ranges, so nothing changes before the operator sets it) (#1083) |
| #1169 | A proxy listener (`LAKE_PROXY_PORT`): client-address headers are believed only on the port the ingress alone can reach, and the main port then trusts no one by default. Off until the operator sets it (orama-operator#961) (#1132) |

## Before it rolls

- **The schema through `0103` reaches each control database before the image.** Either
  orama-operator#965 (the operator runs `lake migrate` from this image, the first that has it), or an
  operator release that vendors `db/schema.sql` through `0103` with `clerk_session_binding_guard`
  selected. A v0.7.0 pod on the v0.6 schema fails Clerk sign-in, grants, coupons and browser keys.
- **No new required setting.** Every new variable (`LAKE_PROXY_PORT`, `LAKE_TRUSTED_PROXY_CIDRS`,
  `LAKE_TERMS_URL`, `LAKE_PRIVACY_URL`, `LAKE_HOST_ALIASES`, `LAKE_CONTROL_HOST`,
  `LAKE_SIGN_IN_SSO_PROVIDER`, `LAKE_BRAND_*`) defaults to today's behaviour; `lake manifest`
  declares them all.
- **After the image:** orama-operator#961 (the proxy port) and #963 (a customer's domain and brand)
  roll only once every Lake runs v0.7.0.
- **Behaviour to know:** revoking a device no longer ends keys made in a browser on it; use
  **Sign out everywhere** to end every credential.
