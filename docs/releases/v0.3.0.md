# v0.3.0

**Released:** 2026-10-19 · **Branch:** `main` · **Previous:** [v0.2.0](v0.2.0.md) (2026-10-17).

Lake is where a customer designs, trains and ships AI on their own data: one C++26 binary that
serves a web app, a REST API and an MCP server over one registry of capabilities. v0.1.0 is the
full inventory of the product; this page lists what changed since v0.2.0. Everything v0.2.0 lists
is still in this release, and no capability was removed.

This release adds the **lake.live order sheet** (four offers with prices, Stripe Checkout for the
paid ones, an order form for every one, Resend email to support and the customer, and a status
page), and the fixes from the **2026-10-18 UX review** ([#820](https://github.com/oramasearch/lake/issues/820)):
datasets named after their file and shown in the file's column order with types, a dataset page
that leads to a model, short pipeline and model names, Check that waits for Approve, Ask Orama
proposals that the capability accepts, and a sign-in runbook for every identity provider.

## 1. The lake.live order sheet

[#833](https://github.com/oramasearch/lake/pull/833), issue [#831](https://github.com/oramasearch/lake/issues/831).
Contract: [`../api/orders.md`](../api/orders.md); page: [`../ui/regions.md`](../ui/regions.md#the-order-sheet).

- **Four offers** on the apex region picker, prices in USD: Shared (usage-based, linked to the price
  list), Private Warehouse ($1,000/month, $400 credit), Dedicated Cluster ($5,000/month, $2,000
  credit, by provider and region), On-Prem (from $10,000/month, 40% credit). Every option includes
  backups. Choosing the shared region is unchanged.
- **One configuration:** a documented default merged with `LAKE_ORDER_SHEET` (an RFC 7386 merge
  patch), validated at startup.
- **Pay path** (Private Warehouse, and a Dedicated Cluster in a region the operator can create): the
  order is recorded `pending_payment` and the person goes to a Stripe Checkout Session (subscription,
  USD, quantity 1). The signed Stripe webhook moves it to `paid` or `cancelled` from the four
  `checkout.session.*` events, once per event. A paid order is for one warehouse or cluster: larger
  orders go through the order form (`cloud_orders_checkout_one`).
- **Order form path** (every offer; On-Prem only this): recorded `submitted` and emailed to support.
- **Email through Resend:** support gets every field; the customer's copy carries nothing the sender
  typed. Delivery state is on the row and retried with backoff. **Resend is a deployment
  dependency:** without `LAKE_RESEND_API_KEY` orders are recorded but no email is sent
  ([`../deployment/resend.md`](../deployment/resend.md)).
- **Status page** `/orders/<id>?token=…` (an HMAC under the instance key, nothing stored):
  `paid`, `provisioning`, `ready` with the host, or `failed`.
- **Abuse limits** on the anonymous form: per-address and global hourly limits, a honeypot, a 32 KiB
  body limit and per-field limits. Every state change is a `cloud_order_events` row and a central
  audit event.
- **Provisioning a paid order is the operator's:** orama-operator#634, in review as orama-operator#635.
  Until it ships, a `paid` order stays `paid` and support takes it from the email.
- Web app: the region menu and Workspaces offer "New setup…" and "On-prem…" from
  `server_info.order_sheet_url`.

## 2. Datasets

- **Named after the file** ([#824](https://github.com/oramasearch/lake/pull/824), issue
  [#814](https://github.com/oramasearch/lake/issues/814)): choosing a file fills Dataset name from
  its name, made valid; a name the person typed is kept.
- **Columns in the answer's and the file's order, with types**
  ([#822](https://github.com/oramasearch/lake/pull/822), [#834](https://github.com/oramasearch/lake/pull/834),
  issue [#812](https://github.com/oramasearch/lake/issues/812)): the Query page and the dataset page
  follow the answer's `columns`, never sorted keys. Columns shows each column's Type and Empty share
  from `get_dataset`'s typed columns; First Rows asks for `LIMIT 20`, and the Query page sends a plain
  `SELECT` with `LIMIT 501`. **The typed columns and the file's order need a workspace engine with
  zetta#1021** ([zetta#1299](https://github.com/oramasearch/zetta/pull/1299)); against an older
  engine the pages fall back to the first rows' types, and against one without `LIMIT` to reading
  the rows as before.
- **A dataset's page leads to a model** ([#825](https://github.com/oramasearch/lake/pull/825), issue
  [#818](https://github.com/oramasearch/lake/issues/818)): **Train a model on this** opens a new
  project with Build pipeline on the dataset; Keep durable is secondary.

## 4. Ask Orama and the agents

- **Proposals the capability accepts** ([#827](https://github.com/oramasearch/lake/pull/827), issue
  [#794](https://github.com/oramasearch/lake/issues/794)): each proposal is checked with the
  registry's own input validation before it is offered; one that would be refused is withheld, and
  the reply names every missing field. A malformed answer no longer loses the turn. A failed confirm
  shows why and offers Try again only for a transient refusal.
- **Auto-Suggest's discover turn** may read apps and builds
  ([#829](https://github.com/oramasearch/lake/pull/829), issue [#795](https://github.com/oramasearch/lake/issues/795)).
- **Ask Orama's guide gives the real path to a first dataset**
  ([#830](https://github.com/oramasearch/lake/pull/830), issue [#817](https://github.com/oramasearch/lake/issues/817)).

## 6. Schema

Two additive migrations, applied by the operator's schema Job before this binary serves. **The
operator must vendor `db/schema.sql` at this tag and select the new guards before this image rolls.**
The operator's `dev` vendors through `0088_repository_liquid_ids`; `0089` is vendored by
orama-operator#635.

| Migration | Adds | Guard |
|---|---|---|
| `0088_repository_liquid_ids` | `repositories.liquid_id` and its index | `repository_liquid_ids_guard` |
| `0089_cloud_orders` | `cloud_orders`, `cloud_order_events`, their indexes, the `updated_at` trigger and the `lake_cloud_orders` notification for a `paid` order | `cloud_orders_guard` |

## Known issues

Security-relevant first.

- **Security: [#562](https://github.com/oramasearch/lake/issues/562)** — `sign_in_sso` issues a
  session for an SSO identity it never verifies. **Do not enable an SSO provider on an instance
  others can reach until this is fixed.** (Open since v0.1.0.)
- **Security: [#838](https://github.com/oramasearch/lake/issues/838)** — the order sheet's rate
  limit trusts a forgeable client address, and its global cap can be used up by anyone to block
  paid orders.
- **Security: [#775](https://github.com/oramasearch/lake/issues/775)** — an invalid, revoked or
  expired bearer is treated as a visitor on capabilities a visitor may call instead of 401.
- **Security: [#774](https://github.com/oramasearch/lake/issues/774)** — `begin_email_recovery`
  tells a visitor whether an email has an account (200 vs 404).
- **Security: [#772](https://github.com/oramasearch/lake/issues/772)** — `deliver_webhook` waits
  for the endpoint on the server's own thread; a slow endpoint stops Lake answering anything.
- **Security: [#773](https://github.com/oramasearch/lake/issues/773)** — `enroll_mfa`'s
  `otpauth://` URI carries a hexadecimal secret where authenticator apps expect base32.
- **Security: https://github.com/oramasearch/orama-operator/issues/492** — the operator copies any
  Secret named in an app row's legacy `secret_env_refs` into the app.
- **Sign-in:** SAML has no endpoint an identity provider can post to
  ([#836](https://github.com/oramasearch/lake/issues/836)), and enterprise OIDC cannot reach Entra,
  Okta or Google Workspace ([#837](https://github.com/oramasearch/lake/issues/837)).
- **Ask Orama:** a proposal that already worked can be confirmed again through the API (the page
  hides the button), and `store_error` counts as transient for Try again.
- [#779](https://github.com/oramasearch/lake/issues/779), [#777](https://github.com/oramasearch/lake/issues/777),
  [#778](https://github.com/oramasearch/lake/issues/778), [#783](https://github.com/oramasearch/lake/issues/783),

## Running it

Lake is deployed by [`oramasearch/orama-operator`](https://github.com/oramasearch/orama-operator)
as a `Lake` resource, from a private `oramasearch/lake:<tag>` image built on the cluster
BuildKit. The operator must vendor this tag's schema (through `0089_cloud_orders`) and select
`repository_liquid_ids_guard` and `cloud_orders_guard` before it serves this binary. The order
sheet needs `LAKE_RESEND_API_KEY` ([`../deployment/resend.md`](../deployment/resend.md)) and the
Stripe keys with the `checkout.session.*` events ([`../deployment/stripe.md`](../deployment/stripe.md)).
See [`docs/deployment/aks.md`](../deployment/aks.md) and
[`docs/control-plane/schema.md`](../control-plane/schema.md).

To build and run locally, see [`docs/build/local.md`](../build/local.md).
