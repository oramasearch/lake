# v0.2.0

**Released:** 2026-10-17 · **Branch:** `main` · **Previous:** [v0.1.0](v0.1.0.md) (2026-10-12).

Lake is where a customer designs, trains and ships AI on their own data: one C++26 binary that
serves a web app, a REST API and an MCP server over one registry of capabilities. v0.1.0 is the
full inventory of the product; this page lists what changed since then. Everything v0.1.0 lists
is still in this release, and no capability was removed.

This release adds **secure networking** (declared connections with scoped credentials, egress
rules, developer tunnels with recipient-only certificates, and a Network section in each
workspace), **regions** and the apex region picker, a **managed key for every new account** with
an optional move to the person's own identity, **Clerk webhooks** that create, update and disable
accounts, **one name per agent** with all nine of Orama's agents offered to people, and a new
**Ask Orama home**.

## 1. Secure networking

Epic [#724](https://github.com/oramasearch/lake/issues/724); the cross-product tracker is
https://github.com/oramasearch/orama-bridge/issues/186. The architecture is
[`docs/architecture/secure-networking.md`](../architecture/secure-networking.md).

- **Desired state in Lake's Postgres** ([#727](https://github.com/oramasearch/lake/issues/727),
  migration `0084_network`): four desired/status pairs (connections, egress rules, tunnel
  grants, peers) matching section 11 of the operator's contract column for column, the guard
  `network_guard`, a `lake_network` notification on each desired write, and signed audit in the
  same transaction as each write. On rollout every existing app-to-service path is seeded once,
  so running apps keep their connectivity; Lake writes no internet-egress rows and the operator
  keeps its implicit rule. See [`docs/control-plane/network.md`](../control-plane/network.md).
- **Fourteen capabilities** through REST, OpenAPI and MCP, permission-checked and audited
  ([#728](https://github.com/oramasearch/lake/issues/728)): declare, list and remove connections;
  declare and list egress rules by DNS name or address range; list peers; the effective rules;
  tunnel sessions and network activity. Session and activity reads answer empty arrays with
  `pending: "zetta#1281"` until Zetta records them. See [`docs/api/network.md`](../api/network.md).
- **Scoped connection credentials** ([#731](https://github.com/oramasearch/lake/issues/731)): an
  app-to-service connection may ask for its own credential (`read` or `write`, optionally one
  schema); `rotate_network_connection_credential` asks the operator to replace it. Lake records
  the scope and shows the workspace-secret reference; the operator creates the native role.
  See [`docs/api/scoped-credentials.md`](../api/scoped-credentials.md).
- **Developer tunnels** ([#730](https://github.com/oramasearch/lake/issues/730), migration
  `0085_network_tunnel_ca`): an account admin grants one member access to one service or app
  port for one hour to 30 days; the member sends a CSR and receives a client certificate signed
  under the customer's PKI authority, the relay endpoint and the relay CA. The private key never
  leaves the member's machine. Grants end by revocation or expiry. See
  [`docs/api/tunnel-grants.md`](../api/tunnel-grants.md).
- **Lake serves the tunnel client** ([#745](https://github.com/oramasearch/lake/issues/745)):
  the image carries the `zetta-tunnel` binaries (macOS arm64, Linux amd64) from
  `oramasearch/zetta-tunnel-clients:v0.1.0`, pinned by digest. `tunnel_client_downloads` gives
  any signed-in person the version and, per platform, the SHA-256, the size and a 15-minute
  signed link, which `GET /tunnel-clients/{platform}` serves without a session. See
  [`docs/api/tunnel-clients.md`](../api/tunnel-clients.md).
- **The Network section** in each workspace, after Ship
  ([#729](https://github.com/oramasearch/lake/issues/729)): Overview, Connections, Developer
  Access, Private Networks, Egress and DNS, Policies and Activity, which together call all
  fourteen network capabilities. Every row shows Waiting, Updating, Ready, Failed, Removing or
  Removed, and pages read again every 3 seconds while a row is still settling (#749).
  **Get credentials** is numbered copy-and-paste steps: make the key and request, paste it, save
  the certificates, install and start the tunnel client, then connect with the service's own
  working command (`psql`, `mysql`, `valkey-cli`, `cqlsh` or `curl`), the password masked until
  **Reveal** (#748, #750, #751). A Ready service in Ship → Services has **Developer access**,
  which opens Grant access filled in. See [`docs/ui/network.md`](../ui/network.md) and the
  [Network guide](../guide/network.md).

What the operator does with these rows (enforcing connections and egress, running the relay,
delivering scoped credentials) is the operator's work and is not claimed by this page.

## 2. Regions

[#757](https://github.com/oramasearch/lake/issues/757), liquid-bridge decision 64.

- **Configuration**: `LAKE_REGION`, `LAKE_REGION_LABEL`, `LAKE_REGIONS` and `LAKE_APEX_HOST`,
  set by the operator when a `LakeSet` member has a region. Unset, Lake behaves as before. An
  invalid value stops startup with a message naming the variable.
- **`server_info`** gains `region` (`{name, label}` or `null`) and `regions`
  (`[{name, label, host}]`).
- **The apex region picker**: a request to `LAKE_APEX_HOST` gets a server-rendered page, working
  without JavaScript, that preselects the `lake_region` cookie, else the region nearest the
  visitor's country (`CF-IPCountry`), else the first; choosing one sets the cookie and redirects
  to that region's host with the same path and query.
- **The web app** names the region in the top bar (with links to the others), on sign-in and
  sign-up, and beside each workspace.

An account exists in one region only, and a workspace cannot move between regions
([#758](https://github.com/oramasearch/lake/issues/758),
[#759](https://github.com/oramasearch/lake/issues/759)). See [`docs/api/regions.md`](../api/regions.md)
and [`docs/ui/regions.md`](../ui/regions.md).

## 3. Identity: a managed key for every account, and your own identity

[#762](https://github.com/oramasearch/lake/issues/762), liquid-bridge decision 65 (amending 44),
migration `0086_identity_links`.

- **Every new account gets a managed key.** Lake's own password sign-up no longer asks for an
  identity document; Lake mints a managed key, as a first Clerk sign-in already did. Application
  pools still require the person's document.
- **Account → Identity** (`/settings?tab=identity`) shows the account identity, the key it signs
  with and what it signs as, and offers **Use my own identity**: `begin_own_identity` verifies the
  output of `liquid identity show --document` (an initial document only) and issues a ten-minute,
  single-use challenge; `use_own_identity` verifies the `liquid sign artifact <challenge>`
  signature, has the managed key sign the link, and in one transaction records the link and
  destroys the managed seed. The account keeps its identifier, so grants, memberships, audit and
  repositories carry over; `sign_in_taap` with the own key reaches it. Linking is one-way.
- **Pushes name their signer**: every `push_change` audit event names `author`,
  `author_account` and `author_is_caller`.

See [`docs/api/identity.md`](../api/identity.md#your-own-identity).

## 4. Clerk webhooks

[#765](https://github.com/oramasearch/lake/issues/765), migration `0087_clerk_webhooks`.

`POST /identity/clerk-webhook` is verified with Lake's own Svix HMAC under
`LAKE_CLERK_WEBHOOK_SECRET` (the route answers 404 without it) and applies each `svix-id` once.
`user.created` provisions the account as a first Clerk sign-in does; `user.updated` sets its
verified email and display name; `user.deleted` disables the account (`users.disabled_at`) and
revokes its sessions, tokens and devices without erasing anything. A disabled account is issued
no session. Only a verified email is linked or stored. Every delivery is one central audit event.
Registering the endpoint and injecting the secret per instance is
https://github.com/oramasearch/orama-operator/issues/541. See [`docs/api/clerk.md`](../api/clerk.md#webhooks).

## 5. Agents: one name each, all nine offered

[#763](https://github.com/oramasearch/lake/issues/763), [#788](https://github.com/oramasearch/lake/issues/788).

- **One source of names**, `include/lake/control/agent_library.hpp`: Ask Orama, Project Agent,
  Application Agent, Experiments Agent, Auto-Suggest Agent, Agent Creator Agent, Eval Generator
  Agent, Auto-Suggest Corpus Agent and Project Corpus Agent. `AgentNames.*` fails when a page,
  guide, document, test or tool spells one differently.
- **No agent is internal.** `list_agent_library` lists all nine (`include_internal` is accepted
  and ignored); the corpus agents build a training corpus for you and the Eval Generator Agent
  creates an eval. Design → Agents shows one *By Orama* list.
- **Talk to** in Ask Orama lists every agent by its library name, with its one-sentence purpose
  and *Where you meet it*; an agent this Lake does not run is shown disabled.

## 6. Ask Orama's home

[#764](https://github.com/oramasearch/lake/issues/764), [#784](https://github.com/oramasearch/lake/issues/784),
[#786](https://github.com/oramasearch/lake/issues/786), [#789](https://github.com/oramasearch/lake/issues/789),
[#791](https://github.com/oramasearch/lake/issues/791).

The empty home (`/`) says what Lake is for (**AI sovereignty**: *when you're tired of renting
someone else's AI, Orama Lake is where you own your AI*), lists the agents you can talk to, and
maps *Design, train and ship production-grade AI*: each rail group (Data, Design, Train, Ship,
Network, Organization, Developer) as a card with its icon, every page with one line and an
example question. The Network group lists all seven Network pages; Developer links MCP Tools and
MCP Worked Flows. A suggested question goes into the message box to edit, instead of being sent.
Only what this Lake runs is shown (Billing only with `LAKE_BILLING`, Deployments only when
`server_info` says so). See [the Ask Orama guide](../guide/ask-orama.md).

## What `v0.2.0` does **not** include

- **A production environment.** Lake runs only on development and nonprod instances; lake.live
  is planned (https://github.com/oramasearch/orama-operator/issues/513,
  [#755](https://github.com/oramasearch/lake/issues/755)).
- **Network enforcement in Lake.** Lake records desired state; the operator enforces it. Tunnel
  session history and network activity are pending in Zetta (zetta#1281), so those reads answer
  empty with `pending`. Network health ([#740](https://github.com/oramasearch/lake/issues/740)),
  usage ([#738](https://github.com/oramasearch/lake/issues/738)) and billing
  ([#739](https://github.com/oramasearch/lake/issues/739)) for networking are not built. Service
  connection credentials are not yet in the workspace's secret store
  ([#629](https://github.com/oramasearch/lake/issues/629)).
- **Tunnel clients** for macOS on Intel, Linux arm64 and Windows
  (https://github.com/oramasearch/zetta-tunnel/issues/26).
- **One identity across regions**, and moving a workspace between regions
  ([#758](https://github.com/oramasearch/lake/issues/758), [#759](https://github.com/oramasearch/lake/issues/759)).
- **Linking an already-rotated identity**: only initial liquid documents are accepted, and a link
  cannot be undone.
- Everything v0.1.0 lists as not included and still open: automatic invoicing
  ([#621](https://github.com/oramasearch/lake/issues/621)), all state in workspace Zettas, Zetta
  parity ([#185](https://github.com/oramasearch/lake/issues/185)), storage phases 2 to 4,
  pagination on every list page ([#227](https://github.com/oramasearch/lake/issues/227)), native
  agents on the Orama base model ([#246](https://github.com/oramasearch/lake/issues/246); see
  also [#799](https://github.com/oramasearch/lake/issues/799) below), changing an agent with the
  Agent Factory ([#271](https://github.com/oramasearch/lake/issues/271)), model destinations and
  drift.

## Known issues

Security-relevant first. Many were found by the end-to-end suite
(https://github.com/oramasearch/orama-operator/issues/537) on `lake-testing` at revision
`51fe838b`, and are open at this tag.

- **Security: [#562](https://github.com/oramasearch/lake/issues/562)** — `sign_in_sso` issues a
  session for an SSO identity it never verifies. **Do not enable an SSO provider on an instance
  others can reach until this is fixed.** (Open since v0.1.0.)
- **Security: [#775](https://github.com/oramasearch/lake/issues/775)** — an invalid, revoked or
  expired bearer is treated as a visitor on capabilities a visitor may call (for example
  `list_repositories` answers 200) instead of 401.
- **Security: [#774](https://github.com/oramasearch/lake/issues/774)** — `begin_email_recovery`
  answers 200 for an email with an account and 404 for one without, so anyone can find out
  whether an address has a Lake account.
- **Security: [#772](https://github.com/oramasearch/lake/issues/772)** — `deliver_webhook` waits
  for the endpoint on the server's own thread; a slow endpoint stops Lake answering anything,
  including its liveness probe.
- **Security: [#773](https://github.com/oramasearch/lake/issues/773)** — `enroll_mfa`'s
  `otpauth://` URI carries a hexadecimal secret where authenticator apps expect base32, so a
  person who enrolls cannot sign in with their authenticator.

  Secret named in an app row's legacy `secret_env_refs` from the Lake namespace into the app.

## Running it

Lake is deployed by [`oramasearch/orama-operator`](https://github.com/oramasearch/orama-operator)
as a `Lake` resource, from a private `oramasearch/lake:<tag>` image built on the cluster
BuildKit. The operator must vendor this tag's schema (through `0087_clerk_webhooks`) and select
`network_guard`, `identity_links_guard` and `clerk_webhooks_guard` before it serves this binary.
Clerk webhooks need `LAKE_CLERK_WEBHOOK_SECRET` and the endpoint registered with Clerk
(https://github.com/oramasearch/orama-operator/issues/541); regions need the `LakeSet` member's
region. See [`docs/deployment/aks.md`](../deployment/aks.md) and
[`docs/control-plane/schema.md`](../control-plane/schema.md).

To build and run locally, see [`docs/build/local.md`](../build/local.md).
