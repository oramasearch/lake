# v0.8.1

2026-10-27. A patch release: the fixes from Steve's customer-insights demo on `us.lake.live`
([lake#1260](https://github.com/oramasearch/lake/issues/1260)).

## What it includes

- **A file's text is its exact UTF-8** ([lake#1238](https://github.com/oramasearch/lake/issues/1238),
  [#1265](https://github.com/oramasearch/lake/pull/1265)). `repository_file` (REST and MCP), `resolve_model_file`
  and `resolve_dataset_file` answer `contents` as the file's exact text with `binary: false`; a file that is not
  UTF-8 has no `contents` and `binary: true`. Before, every non-ASCII byte came back as literal `\xNN` text, and an
  agent that committed what it read wrote the escapes into the file. The drive preview, `diff_drive_versions`,
  `/file/raw` and `/file/download`, methodology sources and the model card use the same rule
  ([repositories](../api/repositories.md#file-contents)). **Clients:** `contents` is absent for a binary file.
- **Clustering never groups by a row number, an identifier or contact details**
  ([lake#1242](https://github.com/oramasearch/lake/issues/1242), [#1264](https://github.com/oramasearch/lake/pull/1264)).
  Columns named like a row number or id are identifiers; clustering also leaves out row numbers recognised by their
  values, free text, names and contact details, and turns a date into its month and its days before the latest.
  With nothing left it refuses, saying why for each column. The demo's "low Index / high Index" segments came from
  this.
- **Predict on a clustering model** ([lake#1243](https://github.com/oramasearch/lake/issues/1243),
  [#1267](https://github.com/oramasearch/lake/pull/1267)). The Model page shows a clustering model's segments and
  tables, and Try it becomes *Place a Row in a Segment*. Against this release's Zetta pin the engine cannot place a
  new row yet, and `predict`, `score` and `explain` say so in plain words (`not_supported`) instead of a schema
  error; zetta [#1499](https://github.com/oramasearch/zetta/pull/1499) adds it, in a later Zetta release.
- **Change App reloads onto the new version** ([lake#1259](https://github.com/oramasearch/lake/issues/1259),
  [#1262](https://github.com/oramasearch/lake/pull/1262)). The split screen's frame reloads again over the minute
  after the App reads Ready, because the operator reported Ready while the old pod still served (fixed in
  orama-operator [#1050](https://github.com/oramasearch/orama-operator/pull/1050)). A confirmed proposal now says
  so. New browser check `tools/e2e/change-app.mjs`.
- **End-to-end fixes:** T3 ranks only at-risk tables that have `account` and `risk`
  ([lake#1258](https://github.com/oramasearch/lake/issues/1258), [#1263](https://github.com/oramasearch/lake/pull/1263));
  T12 studies a dataset keyed by a column the study engine recognises
  ([agent-experiments#32](https://github.com/oramasearch/agent-experiments/issues/32),
  [#1261](https://github.com/oramasearch/lake/pull/1261)).
- **The test runner's stale-database sweep no longer breaks a test's connection**
  ([lake#1254](https://github.com/oramasearch/lake/issues/1254), [#1266](https://github.com/oramasearch/lake/pull/1266)).

Released with it: agent-application v0.2.7 (files read exactly, agent-application#63; filters applied everywhere,
agent-application#64), app-runtime v0.1.3 (Streamlit messages over 1 MiB, app-runtime#26: the demo App's filter),
and orama-operator v0.10.6 (Ready only when the rollout is complete).
