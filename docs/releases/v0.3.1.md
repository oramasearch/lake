# v0.3.1

**Released:** 2026-10-20 · **Branch:** `main` · **Previous:** [v0.3.0](v0.3.0.md) (2026-10-19).

v0.3.1 is **a patch for billing through Stripe in an account Lake shares** with Orama Cloud v1 and
with other Lakes (epic [orama-bridge#199](https://github.com/oramasearch/orama-bridge/issues/199)).
Lake tags every Stripe object it creates as its own and ignores events about anyone else's, itemises
its invoices and Checkout under its own products, replaces a kept Stripe customer that no longer
exists, stores each account's **billing contact** (with a card on the Billing page), and has Stripe
**email each issued invoice** to it. Everything in [v0.3.0](v0.3.0.md) is still here, and no
capability was removed.

## 1. One Stripe account, several apps

#861 and #862 ([`docs/api/billing.md`](../api/billing.md)).

- **Tags.** The customer, the invoice, the order sheet's Checkout Session and its subscription carry
  `metadata[orama_app]=lake` and `metadata[lake_instance]=<LAKE_PUBLIC_HOST>`. Lake never sets
  Cloud v1's bare `team_id`, `plan_id`, `addon_type` or `addon_config`.
- **Foreign events.** An invoice without `lake_customer_id` (or a subscription invoice without
  `lake_order_id` in `subscription_details`), a session without `lake_order_id`, or either naming
  another `lake_instance`, is answered `200 {"received":true,"ignored":true}` after the signature
  check, with no payment event row and no audit event. Objects tagged before `lake_instance`
  existed count as this Lake's.
- **Lake's products.** Each invoice line names `lake_usage` with Lake's price inline (a negative
  rounding line keeps a bare amount); the order sheet's Checkout names `lake_private_warehouse` or
  `lake_dedicated_cluster`, with the location in the subscription's description. Prices stay in
  Lake's own price list. A product the account lacks fails with a message saying the operator
  creates it (orama-operator `spec.payments`).

## 2. Kept customers

#863. Before each invoice Lake reads its kept Stripe customer, and replaces it only on a 404
`resource_missing` or `deleted: true` (any other error keeps it), under the key
`lake-customer-<id>-replaces-<old>`. The stored id changes only while it still holds the one read,
and the replacement is audited (`billing.account.provider_customer_replaced`). **Settle or void a
Lake's open Stripe invoices before switching it to another Stripe account or mode.**

## 3. Billing contacts and emailed invoices

#864, #865 and #866 ([`docs/api/billing.md`](../api/billing.md#billing-contact),
[`docs/ui/billing.md`](../ui/billing.md)).

- **`billing_contacts`** (migration `0090`): one row per account, the email, name and address its
  invoices carry. `billing_account` answers it as `contact`, and until one is saved, the signed-in
  admin's email as `suggested_email`.
- **`set_billing_contact`** (owners, admins and the operator) replaces the contact whole, audits
  `billing.contact.set` with field names only, then updates the Stripe customer; a refusal is
  reported and the saved contact kept. New Stripe customers are created with it.
- **The Billing page** shows a **Billing contact** card, read-only for members, editable for owners
  and admins, and asks for a billing email when there is none and invoices are paid online.
- **Emailed invoices.** Once the invoice is stored, `issue_invoice` asks Stripe to send it
  (`POST /v1/invoices/<id>/send`) when the account has a contact. A failed send leaves the invoice
  issued and `send_failed`, audited; the operator's `resend_invoice` sends it again. A test-mode
  send delivers no email.

## 4. Schema

`0090_billing_contacts` is additive. **The operator must vendor it and roll before this image**
(orama-operator#680; the schema gate holds the image until it has applied).

## What `v0.3.1` does **not** include

Everything under v0.3.0's [*does not include*](v0.3.0.md) is still not included. Also not: a Lake
billing through Stripe anywhere (no environment has `spec.payments` yet; orama-operator#641 to #643),
a label for `send_failed` beyond the fallback "send failed", and Customer Portal or card on file.

## Known issues

Security-relevant first. All open at this tag; none is new in this release.


- **Security: [#562](https://github.com/oramasearch/lake/issues/562)** — `sign_in_sso` issues a
  session for an SSO identity it never verifies. **Do not enable an SSO provider on an instance
  others can reach until this is fixed.** (Open since v0.1.0.)
- **Security: [#838](https://github.com/oramasearch/lake/issues/838)** — the order sheet's rate
  limit trusts a forgeable client address, and its global cap can be used up by anyone to block
  paid orders.
- **Security: [#775](https://github.com/oramasearch/lake/issues/775)** — an invalid, revoked or
  expired bearer is treated as a visitor on capabilities a visitor may call instead of 401.
- **Security: [#774](https://github.com/oramasearch/lake/issues/774)** — `begin_email_recovery`
  tells a visitor whether an email has an account (200 vs 404).
- **Security: [#772](https://github.com/oramasearch/lake/issues/772)** — `deliver_webhook` waits
  for the endpoint on the server's own thread; a slow endpoint stops Lake answering anything.
- **Security: [#773](https://github.com/oramasearch/lake/issues/773)** — `enroll_mfa`'s
  `otpauth://` URI carries a hexadecimal secret where authenticator apps expect base32.
- **Security: https://github.com/oramasearch/orama-operator/issues/492** — the operator copies any
  Secret named in an app row's legacy `secret_env_refs` into the app.
- **Sign-in:** SAML has no endpoint an identity provider can post to
  ([#836](https://github.com/oramasearch/lake/issues/836)), and enterprise OIDC cannot reach Entra,
  Okta or Google Workspace ([#837](https://github.com/oramasearch/lake/issues/837)).
- **Ask Orama:** a proposal that already worked can be confirmed again through the API (the page
  hides the button), and `store_error` counts as transient for Try again.
- [#779](https://github.com/oramasearch/lake/issues/779), [#777](https://github.com/oramasearch/lake/issues/777),
  [#778](https://github.com/oramasearch/lake/issues/778), [#783](https://github.com/oramasearch/lake/issues/783),

- **Agent turns that fail:** [#796](https://github.com/oramasearch/lake/issues/796),
  [#797](https://github.com/oramasearch/lake/issues/797), [#803](https://github.com/oramasearch/lake/issues/803),
  [#804](https://github.com/oramasearch/lake/issues/804).
