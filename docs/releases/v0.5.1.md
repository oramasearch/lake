# v0.5.1

**Released:** 2026-10-24 · **Branch:** `main` · **Previous:** [v0.5.0](v0.5.0.md) (2026-10-24).

A patch so **lake reaches its Zettas**: v0.5.0, built against zetta v0.5.0, reached no Zetta at all,
because zetta's client refuses every connection but loopback until a policy is installed
([#1097](https://github.com/oramasearch/lake/issues/1097)). Everything else is v0.5.0.

> **Read [Before it rolls](#before-it-rolls).** It needs orama-operator v0.9.2 (rolled on every cluster).

## Changes

| PR | Change |
|---|---|
| [#1100](https://github.com/oramasearch/lake/pull/1100) | At startup lake reads `ZETTA_EGRESS_ALLOW` and installs it as the egress policy of zetta's client (`lake::control::install_zetta_egress_policy`). A malformed list stops lake; an empty one leaves only Zettas on loopback reachable. The operator renders `*.svc.cluster.local` ([orama-operator#904](https://github.com/oramasearch/orama-operator/pull/904), v0.9.2) ([`../serving/configuration.md`](../serving/configuration.md)) |
| [#1096](https://github.com/oramasearch/lake/pull/1096) | v0.5.0's notes name its image digest (docs) |

## Before it rolls

- **orama-operator v0.9.2 or later** on the cluster, so the lake Deployment has `ZETTA_EGRESS_ALLOW`.
  Without it lake reaches only loopback Zettas, as v0.5.0 did.
- Everything in [v0.5.0's *Before it rolls*](v0.5.0.md#before-it-rolls): its schema (operator v0.9.1 or
  later, rolled) and zetta v0.5.0 on the workspace Zettas.

## What it does not include

- `/readyz` failing while the bus Zetta refuses every call (filed with #1097).

## Known issues

Those of [v0.5.0](v0.5.0.md#known-issues), and:
- **Password sign-up bypasses Clerk's restricted sign-up** ([#1098](https://github.com/oramasearch/lake/issues/1098)).
- Sign-in timing reveals which emails have accounts ([#1101](https://github.com/oramasearch/lake/issues/1101)).
- The e2e scripts drive the old console ([#1099](https://github.com/oramasearch/lake/issues/1099)).

## Verification

- `Workspaces.TheOperatorsEgressListLetsLakeReachItsZettasAndNothingElse` and all 50 `Workspaces` tests
  pass (macOS, against zetta v0.5.0); `ZETTA_EGRESS_ALLOW=bad:99999 lake` exits 2.
- **On `dev`** (`dev-624f9aa0`, the same source as this tag apart from the version): a workspace Zetta
  answers `workspace_engine_info` and a `workspace_sql` select, the agent bus takes tasks, safe mode's
  defaults, warnings and *Run This Query?* pass, as do Clerk sign-in, the generic 401 and MCP
  ([#1087](https://github.com/oramasearch/lake/issues/1087)). The model gateway and Ask Orama Confirm
  were rerunning after the OpenAI key was replaced (#1102).
- **The full suite was not rerun for this patch**, and it was rolled to every environment at once
  (Steve, 2026-10-24: *"put 0.5.1 to everywhere now"*, launch day). v0.5.0's full run is in its notes.
