# v0.5.0

**Released:** 2026-10-24 · **Branch:** `main` · **Previous:** [v0.4.0](v0.4.0.md) (2026-10-21).

v0.5.0 finishes **the pre-launch security review** in Lake and the liquid#383 identity
fix, and adds **safe mode per database** (Off / Warn Writes / Warn All) with a dialog that shows the
exact query before a warned one runs. It is built against **zetta v0.5.0**. Five migrations
(`0094` to `0098`) the operator vendors before the image rolls. 36 pull requests since v0.4.0.

> **Read [Before it rolls](#before-it-rolls).** It needs an operator release with its schema, the Clerk
> secret key and new webhook events, and zetta v0.5.0 on the workspace Zettas first.

## 2. Features

- **Safe mode per database and connection** (#1080,
  with zetta#1373, #906):
  the level is a control in the query editor's status bar, a column on the connections list and a field
  on each connection. A warned query opens *Run This Query?* with each statement exactly as it will
  run. **A database defaults to Off; a connection to Warn Writes**.
- **Model prices**: the default models (gpt-5.5, gpt-5, gpt-4o, text-embedding-3-small) have seeded
  prices (#1065); only configured models are served.
- **A manual UI test runbook** for every console page, 968 cases (#1072).

## 3. Behaviour that changes

- **Sign-in:** failed password, MFA and recovery checks answer one generic 401; 10 failures per account
  and 100 per client address in 15 minutes lock that account or client for the window, shared across
  replicas (#1077, no instance-wide ceiling). A TOTP code works once. MFA enrollment needs the current
  password (#1060).
- **Existing recovery codes stop working** (#1074): people re-enroll to get new ones. All data so far is
  test data.
- **Clerk:** a revoked Clerk session, a ban, a lock or a deprovision revokes Lake sessions, tokens and
  devices account-wide and suspends the account; every Clerk exchange checks Clerk live (#1054).
  Migration `0094` signs every Clerk-linked account out once.
- **Email recovery** reuses an open attempt and is bounded per account, client and overall; owners can
  cancel from the device notice (#1069).
- **Ask Orama's Confirm** needs the `input_sha256` of the exact proposed call (#1047); API callers that
  confirm without it get 400 (lake-e2e: lake-e2e#4).
- **Request bodies** are capped (1 MiB by default, 64 MiB for bulk inputs, 256 KiB anonymous MCP); remote
  MCP and OAuth JSON deeper than 64 levels is refused (#1048, #1059).
- **Console Markdown renders images as text**, and every page refuses images from other origins (#1050).
- **Imported repository metadata** names the importer as its author (#1053). **Owner changes** need a
  current owner (#1066). **Storage quotas** are set by the operator or instance administrator only, and
  the Usage page offers them only there (#1078).
- **Model gateway:** closed request schemas and only metered features (#1064); only configured models,
  each priced (#1065).
- **Release verification** binds artifacts to their attested source; a protected branch with
  `required_verification` refuses pushes until producers sign the new claims (#1082).
- **Cloud orders** record their paid-through date and a 3-day grace; `cloud_order_desired_state` is
  `suspended` after it (#1073). The operator does not act on it yet
  (orama-operator#897: sleep, never delete).

## Before it rolls

- **An operator release** that vendors `db/schema.sql` through `0098_authentication_attempts` (guards
  `clerk_revocation_guard`, `model_token_prices_guard`, `email_recovery_limits_guard`,
  `cloud_order_entitlements_guard`, `authentication_attempts_guard`), gives lake
  `LAKE_CLERK_SECRET_KEY`, subscribes its Clerk webhook to the `session.*` events (#1054) and registers
  the Stripe subscription and invoice events (#1073). Without the secret key, Clerk sign-in fails closed.
- **zetta v0.5.0 on the workspace Zettas** (after operator v0.9.0), since lake v0.5.0 talks to Zetta's
  safe mode and new capabilities.
- Rolling needs the maintainers' consent, through the set files.

## What v0.5.0 does not include

- The proxy service for agent launches (#1039); the
  per-launch token PR #878 was rejected as superseded.
- Lake's liquid identity on the store volume, then deleting the test repositories (#1081).

## Known issues

- **Per-client limits trust `X-Real-IP` from any peer** (#1083):
  behind the ingress it is Cloudflare's `CF-Connecting-IP`, but lake accepts it from any sender and no
  NetworkPolicy keeps in-cluster callers (LakeApps included) off lake's port. Such a caller could rotate
  it to exhaust the global email-recovery budget (recovery blocked for an hour) or fill the attempts
  table, which caps live keys at 100,000 (new clients then get `rate_limited`).
- Release producers do not sign the new source claims yet (#1082).
- The base-model error message after zetta#1465 (#1079).
- History signed by earlier pods' identities cannot sync to a client on liquid#448
  (liquid#452); all such data is test data (#1081).
