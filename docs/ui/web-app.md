# The web app

lake#561 replaced the server-rendered pages (`src/api/web_ui*.cpp`) with a single-page app in
`frontend/`, built the way `oramasearch/rev-os` builds its frontend: React 19, Vite 6, Tailwind 4,
TypeScript, TanStack Query and React Router. Lake's styling did not change: the app uses the same
Orama design tokens, the same IBM Plex faces and the same component classes the pages used.

## What it is

- **One app, served by lake.** CMake builds `frontend/` with npm and
  `tools/ui/embed-frontend.mjs` embeds `dist/` into the binary (`include/lake/api/web_app.hpp`).
  Lake answers every page route with `index.html` (`Cache-Control: no-cache`,
  `Content-Security-Policy: frame-ancestors 'self'`) and serves the content-hashed files under
  `/ui/` immutable for a year. No file is read at run time.
- **It calls only lake's API.** Every read is `GET /v1/<capability>` and every change
  `POST /v1/<capability>`: the same capabilities, authorization and audit as REST and MCP
  (`docs/api/README.md`). The app can do nothing the API cannot. The exceptions are the
  sign-in routes that set or clear the HttpOnly `lake_session` cookie (`POST /session`,
  `POST /logout`, `POST /identity/clerk-session`, the OAuth callback) and the download routes
  that answer bytes (`/file/raw`, `/file/download`, `/drive/download`, `/exports/download`,
  `/share/:token/download`).
- **The credential is the cookie.** Sign-in sets `lake_session`; the page never sees or stores the
  secret. A 401 shows *Your session has ended* with **Sign in again**, and the page stays as it was.
- **Hosted application pages stay on the server.** The sign-in pages an identity application shows
  its own users (`/apps/:id/*`, custom sign-in domains), `/apps/authorize` and `/v1/apps/auth`
  are rendered by lake, in the application's colours, and work without JavaScript.

## The look

The app follows rev-os's visual language on lake's own colours and type (Steve, 2026-10-10):

- a 2px brand strip;
- a 232px rail of lake's groups with lucide icons, where the current group is open and lists its
  pages on a hairline;
- a slim, blurred top bar with the breadcrumb, a workspace pill, a search box (⌘K) and Ask Orama;
- mono uppercase kickers for eyebrows, section titles, table heads and field labels;
- 6px hairline cards and tables;
- 32px controls;
- dashed empty states;
- a dark sign-in plane with the brand on the left and the form card on the right.

`src/styles/look.css` restyles lake's component classes in place, so every page built from them
takes the look without being rewritten. The shell (`components/Shell.tsx`), the workspace picker
and the sign-in frame (`pages/account/AuthFrame.tsx`) draw themselves with Tailwind utilities bound
to the same tokens. The colours stay lake's: the action blue, the light and dark surfaces, and IBM
Plex. The look adds one token, `--lake-rule`, a softer control border.
The shell resets the buttons in its own header and navigation so its utilities alone draw them; a
page's header (`.page-header`) is excluded, so the buttons in a page's actions keep the kit's look.

## The first paint

Lake answers a page request with `index.html` and this request's `viewer` answer embedded as
`<script id="lake-viewer" type="application/json">`. It is the same capability the app would
call first, so the shell and the page start without a round trip. Because the answer is personal,
the page is sent `Cache-Control: private, no-store`. Three more things keep later steps short:

- **The workspace status starts with the page's code.** A workspace page's gate reads
  `workspace_status` first; the session starts that read alongside the code.
- **Every page's code is fetched while the browser is idle**, after the first page is up, so
  later navigation does not wait on a chunk.
- **One shell stays mounted across navigation**, as a layout route; only the page area waits.

## Rules for a page

- **Keep lake's URLs.** Every page keeps its path and query parameters (`/repository?id=…`,
  `/w/<workspace>/design/project?name=…`). They are linked from email, the docs and other tools.
- **Workspace pages live under `/w/<id>/`.** A screen with `workspace: true` is served at both
  addresses; the unprefixed one opens the remembered or only workspace. Capabilities called from it
  go to `/w/<id>/v1/<name>` automatically.
- **A failed read never looks like an empty list.** Use `Query` or give `DataTable` its `q`; the
  build fails otherwise (`scripts/check-list-errors.mjs`).
- **Effects have block bodies.** `useEffect(() => { … })`; the build checks it
  (`scripts/check-effects.mjs`).
- **Words, not stored values.** Show labels, not codes; dates through `format.ts`.
- **Title Case** for headings and rail items, sentence case for body text, buttons and labels
  (`docs/ui/design-system.md` → *Capitalization*).
- **Copy stays as it was.** Headings, explanations, empty states and confirmations keep lake's
  existing wording unless it was wrong.
- **Confirmations name what happens** ("Delete the repository?"), never "Are you sure?".
- **Markdown is rendered in the browser** with `react-markdown` and `remark-gfm`, never with raw
  HTML.
- **Live views poll or long-poll the capability** that the server page's script called; nothing
  refreshes the whole page.

## How a page runs

- **The viewer comes first.** `SessionProvider` (`src/lib/session.tsx`) reads `viewer` once
  (fresh for a minute) and renders nothing else until it answers. The rail, the picker, the guards
  and the forms read it; a failed `viewer` read renders the app as a visitor.
- **Pages are code-split.** Every screen is `lazyPage(() => import(...))` (`src/lib/lazyPage.ts`),
  so a page's code loads the first time it is opened. A tab opened before a deploy asks for chunk
  names the new build no longer has; the first failed import reloads the page once, and a second
  within a minute shows the error instead of looping.
- **Reads are cached for 15 seconds** and are not refetched on window focus. A `4xx` is shown at
  once; only a network failure or a `5xx` is retried, twice (`queryClient` in `src/lib/api.ts`).
- **Every successful write refreshes every read on screen.** Reads that must be sent as `POST`
  (`workspace_query`, the `delete_workspace` dry run) go through `postRead`/`usePostRead`, which
  refresh nothing; calling them through `act` would refetch themselves forever.
- **Live views** poll or long-poll their capability and stop when the page closes:

| What | How |
|---|---|
| An agent task (Ask Orama, Agent Factory, ApplicationAgent, ExperimentsAgent, Project Agent) | `get_agent_task` every 2 s while it works (3 s for the Project Agent's pipeline turns and the Opportunities scan) |
| A project with a running build, proposal or run; a run page | every read again every 3 s; a run every 15 s while it runs |
| A workspace being prepared | `workspace_status` every 15 s (`components/WorkspaceGate.tsx`) |
| App events, build logs | `receive_app_events`, `receive_build_events` long polls, resuming from a cursor kept in `localStorage` |
| Environment logs | `environment_logs` every 3 s from `next_since`, appending lines |
| Experiments | `tail_experiment_events` long polls ([experiments.md](experiments.md#live-updates)) |
| Streams Live | `browse_stream` forward long polls ([streams.md](streams.md)) |

## What the browser keeps

Nothing stored in the browser is a credential or an API default.

| Key | Storage | What |
|---|---|---|
| `lake-theme` | `localStorage` | `light` or `dark`; absent follows the system. `index.html` applies it before the styles load. |
| `lake-rail` | `localStorage` | whether the rail is collapsed |
| `lake-workspace` | `localStorage` | the last workspace opened under `/w/<id>/`; navigation memory only ([workspace-selection.md](workspace-selection.md)) |
| `lake-app-events:<app>`, `lake-build-events:<build>` | `localStorage` | the next event sequence to read, so reopening an app resumes |
| `lake-ask-panel:<workspace>` | `sessionStorage` | the Ask Orama panel's conversation, task and agent for this tab |
| `lake-chunk-reload` | `sessionStorage` | when the page last reloaded for a missing chunk |
| `lake-speech-to-text` | `sessionStorage` | `off` once lake answered `not_supported` to a transcription: the microphones stay hidden for the tab |

## Build and check

```sh
cd frontend
npm ci
npm run dev          # Vite on :5173, proxying the API to LAKE_ORIGIN (default http://127.0.0.1:4900)
npm run typecheck
npm test             # tests/*.test.ts with Node's test runner
npm run build        # tsc, the tests, vite build and both source checks
```

`cmake --build build` runs `npm ci` and `npm run build` itself; `-DLAKE_FRONTEND_DIST=<dist>`
embeds an already-built app instead (the image's Node stage).
