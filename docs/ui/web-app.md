# The web app

lake#561 replaced the server-rendered pages (`src/api/web_ui*.cpp`) with a single-page app in
`frontend/`, built the way `oramasearch/rev-os` builds its frontend: React 19, Vite 6, Tailwind 4,
TypeScript, TanStack Query and React Router. Lake's styling did not change: the app uses the same
Orama design tokens, the same IBM Plex faces and the same component classes the pages used.

## What it is

- **One app, served by lake.** CMake builds `frontend/` with npm and
  `tools/ui/embed-frontend.mjs` embeds `dist/` into the binary (`include/lake/api/web_app.hpp`).
  Lake answers every page route with `index.html` (`Cache-Control: no-cache`,
  `Content-Security-Policy: frame-ancestors 'self'`) and serves the content-hashed files under
  `/ui/` immutable for a year. No file is read at run time.
- **It calls only lake's API.** Every read is `GET /v1/<capability>` and every change
  `POST /v1/<capability>`: the same capabilities, authorization and audit as REST and MCP
  (`docs/api/README.md`). The app can do nothing the API cannot. The exceptions are the
  sign-in routes that set or clear the HttpOnly `lake_session` cookie (`POST /session`,
  `POST /logout`, `POST /identity/clerk-session`, the OAuth callback) and the download routes
  that answer bytes (`/file/raw`, `/file/download`, `/drive/download`, `/exports/download`,
  `/share/:token/download`).
- **The credential is the cookie.** Sign-in sets `lake_session`; the page never sees or stores the
  secret. A 401 shows *Your session has ended* with **Sign in again**, and the page stays as it was.
- **Hosted application pages stay on the server.** The sign-in pages an identity application shows
  its own users (`/apps/:id/*`, custom sign-in domains), `/apps/authorize` and `/v1/apps/auth`
  are rendered by lake, in the application's colours, and work without JavaScript.

## How it is built

| Path | What |
|---|---|
| `src/index.css` | Tailwind's theme and utilities (no preflight), then lake's layers: `styles/tokens.css` (generated by `tools/ui/build-tokens.mjs`, never edited), `styles/fonts.css`, `styles/lake.css` (lake's component classes) and `styles/app.css` (what the app adds: overlays, the rail, the palette, fields). Tailwind's colours, fonts and radii are bound to the lake tokens, so a utility cannot bring in a colour outside the design system. |
| `src/lib/api.ts` | `read(name, input)`, `act(name, input)`, `useRead`, `useList`, `useAct`. Every successful write refreshes every read on screen. The workspace prefix (`/w/<id>`) is added from the page URL. |
| `src/lib/ui.tsx` | The kit: `Page`, `Section`, `Card`, `Grid`, `KeyValue`, `Button`, `Actions`, `Tabs`, `StateTabs`, `Badge`, `Status`, `Notice`, `Empty`, `Skeleton`, `ErrorBlock`, `Query`, `DataTable`, `CopyBlock`, `Mono`, `Kbd`, `Field`, `Form`, `fieldError`. |
| `src/lib/overlay.tsx` | `Modal`, `Drawer`, `ConfirmButton`. The only surfaces with a shadow. |
| `src/lib/toast.tsx` | `useToast()` for a short confirmation after a write. |
| `src/lib/session.tsx` | `useSession()`: the `viewer` read (who is signed in, the operator, the spaces and their workspaces, Clerk), the current workspace and space. |
| `src/lib/trail.tsx` | `useTrail([...])` sets a page's breadcrumb; `entityCrumb` shortens ids. |
| `src/lib/format.ts` | Dates (a date-only value keeps its day in every time zone), numbers, `bytes`, `shortId`. |
| `src/routes.tsx`, `src/routes/types.ts` | The route registry. Each page group owns `src/pages/<group>/routes.ts`; `routes.tsx` joins them and holds the rail (`NAV`) in lake's order. |
| `src/components/Shell.tsx` | The rail, top bar, breadcrumb, workspace picker, Go to (⌘K or `/`), theme switch, Ask Orama panel and account menu. |

## Rules for a page

- **Keep lake's URLs.** Every page keeps its path and query parameters (`/repository?id=…`,
  `/w/<workspace>/design/project?name=…`). They are linked from email, the docs and other tools.
- **Workspace pages live under `/w/<id>/`.** A screen with `workspace: true` is served at both
  addresses; the unprefixed one opens the remembered or only workspace. Capabilities called from it
  go to `/w/<id>/v1/<name>` automatically.
- **A failed read never looks like an empty list.** Use `Query` or give `DataTable` its `q`; the
  build fails otherwise (`scripts/check-list-errors.mjs`).
- **Effects have block bodies.** `useEffect(() => { … })`; the build checks it
  (`scripts/check-effects.mjs`).
- **Words, not stored values.** Show labels, not codes; dates through `format.ts`.
- **Title Case** for headings and rail items, sentence case for body text, buttons and labels
  (`docs/ui/design-system.md` → *Capitalization*).
- **Copy stays as it was.** Headings, explanations, empty states and confirmations keep lake's
  existing wording unless it was wrong.
- **Confirmations name what happens** ("Delete the repository?"), never "Are you sure?".
- **Markdown is rendered in the browser** with `react-markdown` and `remark-gfm`, never with raw
  HTML.
- **Live views poll or long-poll the capability** that the server page's script called; nothing
  refreshes the whole page.

## Build and check

```sh
cd frontend
npm ci
npm run dev          # Vite on :5173, proxying the API to LAKE_ORIGIN (default http://127.0.0.1:4900)
npm run typecheck
npm test             # tests/*.test.ts with Node's test runner
npm run build        # tsc, the tests, vite build and both source checks
```

`cmake --build build` runs `npm ci` and `npm run build` itself; `-DLAKE_FRONTEND_DIST=<dist>`
embeds an already-built app instead (the image's Node stage).
