# lake — internal documentation

One folder per topic, one file per subject. The root README is the front door; this index points
to the detailed contracts and records.

[api/tunnel-grants.md](api/tunnel-grants.md) defines recipient-only tunnel CSR signing, trust,
revocation and pending session history (lake#730); [build/tunnel-grants-proof.md](build/tunnel-grants-proof.md)
records its native proof and coordinator handoff.
[api/tunnel-clients.md](api/tunnel-clients.md) defines the tunnel client downloads: the binaries
copied into the image, `tunnel_client_downloads` and its signed short-lived links, and
`GET /tunnel-clients/<platform>` (lake#745).
[api/regions.md](api/regions.md) defines regions (lake#757, decision 64): `LAKE_REGION`,
`LAKE_REGION_LABEL`, `LAKE_REGIONS` and `LAKE_APEX_HOST`, `server_info`'s `region` and `regions`, and
the apex host's region picker with its closest-region choice and preference cookie;
[ui/regions.md](ui/regions.md) is where the web app shows the region.
[api/orders.md](api/orders.md) defines the apex order sheet (lake#831): offers and prices from
`LAKE_ORDER_SHEET`, Stripe Checkout and the order form, `cloud_orders` (migration `0089`, the
contract orama-operator#634 provisions from), Resend email and the status link;
[ui/regions.md](ui/regions.md#the-order-sheet) is the page.
[api/scoped-credentials.md](api/scoped-credentials.md) defines an app connection's credential
scope, workspace-secret reference, rotation and revocation (lake#731);
[build/scoped-credentials-proof.md](build/scoped-credentials-proof.md) records its native proof
and the remaining operator integration acceptance.

[api/errors.md](api/errors.md) lists every error code a capability answers with its REST status,
the 401 `missing`/`invalid`/`expired` contract and where `path` comes from;
[api/naming.md](api/naming.md) gives the one name each concept has across capabilities and the
deprecated aliases still accepted (lake#450).

[control-plane/workspaces.md](control-plane/workspaces.md) defines migration 0039, workspace
desired state, operator notifications, the schema guard and the approved dev-cluster cutover.
Its native verification is recorded in [build/workspace-contract-proof.md](build/workspace-contract-proof.md).
