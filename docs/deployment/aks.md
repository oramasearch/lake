# `Lake/prod` on AKS

The production lake instance runs on the sandbox AKS cluster `orama-production-cluster-01`,
deployed by `oramasearch/orama-operator` from one `Lake` resource. This page is the current
state and the runbook; the CR's field reference is the operator's `docs/crd-reference.md`.

## What exists (2026-09-02)

| | |
|---|---|
| `Lake` | `prod`, cluster-scoped, `spec.namespace: lake` |
| lake pods | Deployment `lake-prod`, **3 replicas**, image `oramasearch/lake:20260902`, args `--listen 0.0.0.0:4900 --node prod`, readiness `GET /` |
| Service | `lake-prod`, ClusterIP 80 → 4900 |
| Control DB | CNPG `lake-prod-controldb`, 1 instance, **50Gi**, Postgres 18; schema `0001_identity_and_customers` applied (`PostgresSchema lake-prod-controldb-schema`) |
| Ingress | `lake-prod`, class nginx, host `lake.oramadev.net`, whole host → the Service |
| DNS | `CloudflareDNSRecord lake-prod-dns`, proxied, → the shared ingress address |
| Secrets in `lake` | `oramasearch-dockerhub` (pull), `cloudflare-api-token` (`oramadev.net` zone), both copied from `orama-system`; `lake-prod-controldb-app` + CA/TLS generated by CNPG |
| URL | https://lake.oramadev.net (`/`, `/v1/server_info`) |
| Operator | helm release `orama-cloud-v1-operator` in `orama-system`, image `oramasearch/orama-operator:lake-crd-8058ab5` (PR #118 branch) |

`lake.live` is not wired yet: it needs a Cloudflare zone token Secret for that zone in the
`lake` namespace (bridge issue #5).

## Runbook

**Roll a new lake image.** Build natively on amd64 (see [`../build/container-image.md`](../build/container-image.md)),
push an immutable tag, then change `spec.image` on the Lake and apply; the Deployment rolls.

**Roll the operator.** From the operator repo on the branch to deploy:

```sh
docker buildx build --platform linux/amd64 -t oramasearch/orama-operator:lake-crd-<sha> --load .
docker push oramasearch/orama-operator:lake-crd-<sha>
kubectl apply -f config/crd/bases/orama.cloud_lakes.yaml          # helm never upgrades crds/
helm upgrade orama-cloud-v1-operator ./chart -n orama-system \
  --set operator.image.repository=oramasearch/orama-operator \
  --set operator.image.tag=lake-crd-<sha> \
  --set 'operator.imagePullSecrets[0].name=oramasearch-dockerhub'
kubectl rollout status deploy/orama-cloud-v1-operator -n orama-system
```

Immutable tags, never `v1-sandbox` with `IfNotPresent`: the operator docs record the stale-cache
failure that motivates this.

**Create a Lake.** Namespace and the two Secrets first, then the Lake:

```sh
kubectl create namespace <ns>
for s in oramasearch-dockerhub cloudflare-api-token; do
  kubectl get secret $s -n orama-system -o json \
    | python3 -c 'import json,sys; s=json.load(sys.stdin); s["metadata"]={"name":s["metadata"]["name"],"namespace":"<ns>"}; print(json.dumps(s))' \
    | kubectl apply -f -
done
kubectl apply -f lake.yaml
kubectl wait lake/<name> --for=jsonpath='{.status.schemaPhase}'=Applied --timeout=600s
```

**Verify.** `kubectl get lake <name>` → READY = replicas, DB `1/1`, SCHEMA `Applied`, PHASE
`Ready`; `curl https://<host>/v1/server_info`. The manager logs filtered on
`"controller": "lake"` show reconcile errors.

**Delete.** `kubectl delete lake <name>` removes everything it owns, including the CNPG cluster
and **its data**; the namespace is not owned and stays.

## Not production-grade yet

- One Postgres instance, no backups (operator issue #122 for hardening; CNPG backup config is a
  `spec.postgres` addition).
- No resource limits, liveness probe or PodDisruptionBudget on the lake pods.
- TLS terminates at Cloudflare only; the Ingress is port 80.
- The lake binary does not open its control-DB connection yet; the pods that started before the
  Secret existed see an empty `LAKE_CONTROL_DB_URI` until their next restart.
- Zetta data plane not provisioned (operator issue #125).
